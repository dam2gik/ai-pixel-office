# Pixel Office

Electron + Three.js로 만든 로컬 AI 오피스입니다. CEO가 목표를 입력하면 PM이 업무를 나누고, 직원들이 독립 업무를 병렬 실행합니다. 선행 작업의 결과와 산출물 경로를 후속 담당자에게 전달한 뒤 PM이 최종 보고서를 작성합니다.

## 실행

- Windows 실행 파일: `release/Pixel Office 0.3.0.exe`
- 소스에서 실행: `npm install` 후 `npm start`
- Node.js 22.12 이상이 필요합니다. 개발 검증에는 Node.js 24를 사용했습니다.

처음에는 **시뮬레이션 모드**로 시작합니다. 이 모드는 AI를 호출하거나 실제 업무 산출물을 만들지 않습니다. 앱 설정과 협업 흐름을 체험할 수 있습니다.

### v0.3 넓어진 오피스와 생활 모션

- 맵을 15×11에서 **32×22**로 확장했습니다. 워크스페이스, 커피 머신·냉장고·간식장이 있는 탕비실, 안마의자 2대와 소파가 있는 휴게실, 화이트보드·회의 테이블·스크린이 있는 회의실, 칸막이와 세면대가 있는 화장실을 추가했습니다.
- 업무가 없는 직원은 공간을 돌아다니며 커피 마시기, 간식 먹기, 안마의자에서 쉬기, 소파에서 졸기, 스트레칭, 아이디어 회의, 화장실 이용 후 손 씻기를 합니다. 말풍선은 생활 모션이며 실제 AI 작업 결과가 아닙니다.
- 격자 경로 탐색과 정확한 선분 충돌 검사로 벽·가구를 피합니다. 휴식 장소는 직원별로 예약하여 같은 안마의자나 화장실 칸에 동시에 배정하지 않습니다. 이동 중 직원끼리의 물리 충돌 시뮬레이션은 없습니다.
- 진행 중이거나 대기 중인 업무를 받은 직원은 휴식을 끝내고 책상으로 복귀합니다. 이 이동은 시각적 표현이며 실제 Codex 작업을 지연시키지 않습니다. 생활 모션은 로컬에서만 실행되며 AI 호출을 추가하지 않습니다.
- 왼쪽 **공간 둘러보기**나 맵의 공간 이름을 클릭하면 해당 공간으로 확대합니다. **전체 보기** 또는 우측 하단 초기화 버튼으로 돌아옵니다. 마우스 오른쪽 드래그로 시야를 이동할 수 있습니다.
- **생활 모션 켜짐/꺼짐** 선택을 기기에 저장합니다. 기본은 켜짐입니다. 운영체제의 모션 줄이기 설정도 따릅니다. 생활 모션은 최대 24 FPS, 업무 모션은 최대 30 FPS, 카메라 조작은 최대 60 FPS로 제한합니다. 모션을 끈 유휴 상태 및 창 최소화·숨김 상태에서는 렌더링을 정지합니다.
- 움직이는 직원에는 가벼운 접지 그림자를 사용하고, 방과 가구의 그림자는 구성이 변경될 때만 다시 계산합니다. 정적 블록 인스턴싱과 로컬 Pretendard는 유지했습니다.
- 12개 책상에서 모든 시설까지 도달하는 경로, 벽·가구 충돌, 좌석 예약, 화장실 후 손 씻기, 업무 복귀, 모션 정지, 직원 추가 시 상태 보존을 테스트했습니다. 엔진 10개와 생활 시뮬레이션 5개, Electron 화면 테스트를 통과했습니다. 초기 4명 확장 맵의 draw call은 테스트 환경 기준 149회입니다.

### v0.2 전체화면 오피스

- 앱은 게임처럼 전체화면 3D 오피스로 시작합니다. 좌측 상단 햄버거 메뉴에서 직원 관리·추가, 꾸미기, 업무 보드, 협업 기록, PM 보고서, 설정을 엽니다.
- 직원 클릭 시 오른쪽 상세 패널이 열립니다. 업무 보드와 보고서는 오피스 위에 겹쳐지는 패널입니다. 아래 CEO 입력창으로 업무를 맡깁니다.
- 우측 상단 버튼이나 **F11**로 창 모드/전체화면을 전환합니다. **Esc**는 열린 패널을 닫고, 패널이 없으면 전체화면을 해제합니다. 메뉴에서도 화면 전환과 앱 종료가 가능합니다.
- 한글 Pretendard Variable 1.3.9를 로컬 리소스에서 복사해 `public/fonts/`에 포함했습니다. 설치된 폰트나 외부 CDN 없이 동작하며 라이선스 파일도 함께 배포합니다.
- 정적인 블록은 재질별 GPU 인스턴싱으로 묶었습니다. 유휴 상태에는 다시 그리지 않고, 작업 애니메이션은 최대 30 FPS, 카메라 조작은 최대 60 FPS로 동작합니다. 창 최소화/숨김 시 렌더링을 멈춥니다.
- 픽셀 비율을 최대 1.5로 제한하고 그림자 맵을 1024로 줄였습니다. 정적인 그림자는 직원·가구 구성이 바뀔 때 갱신합니다. 캐릭터의 작은 작업 동작마다 그림자를 다시 계산하지 않습니다.
- 가구 변경 시 직원을 다시 생성하지 않고, 공유 geometry/material을 재사용합니다. DOM 이름표는 좌표가 달라질 때만 수정하고, 실시간 메시지 UI 업데이트는 모아서 반영합니다.
- 실제 Electron 테스트에서 초기 4명 장면의 draw call 81회, 유휴 1초간 추가 렌더 0회, 작업 애니메이션 1초간 29프레임, 최소화 상태 추가 렌더 0회를 확인했습니다. 수치는 테스트 환경 기준이며 직원·가구 수와 디스플레이에 따라 달라집니다. 측정 파일: `test-results/render-metrics.json`.

## 실제 Codex 사용

1. 설정 → **연결 확인**을 누릅니다. 설치된 `codex` 또는 VS Code Codex 확장의 실행 파일을 자동으로 찾습니다. 자동 탐색이 실패하면 `codex.exe`를 직접 선택하세요.
2. 기존 ChatGPT 로그인을 사용할 수 있으면 연결됩니다. 필요한 경우 **ChatGPT로 로그인**을 누르고 기본 브라우저에서 로그인한 다음 다시 연결을 확인하세요.
3. 산출물을 저장할 폴더를 선택하세요.
4. 실행 모드를 **Codex**로 변경하고 저장합니다. 병렬 실행은 1~6개로 설정할 수 있습니다.
5. CEO 지시창에서 업무를 맡깁니다. 캐릭터나 직원 목록을 클릭하면 실행 내용 확인 및 추가 지시가 가능합니다.
6. **협업 기록**에서 직원 간 결과 전달을, **PM 보고서**에서 최종 보고와 산출물 폴더를 확인하세요.

별도 OpenAI API 키는 사용하지 않습니다. 앱은 ChatGPT 로그인 유형을 확인하고 실행하며, 사용량과 모델 접근 권한은 해당 계정의 Codex 이용 조건을 따릅니다. Windows ChatGPT 앱 자체를 화면 자동화하는 방식은 아닙니다. 공식 로컬 `codex app-server`와 통신합니다.

## 구현된 협업 방식

- PM이 구조화된 계획을 작성합니다. 작업 ID, 담당 직원, 지시, 선행 작업 목록을 검증합니다.
- 실행 큐가 동시 실행 수를 제한합니다. 같은 직원에게 동시에 두 작업을 맡기지 않습니다.
- 선행 작업이 모두 완료되면 후속 작업을 실행합니다. 선행 결과 본문과 산출물 폴더 경로를 입력으로 전달합니다.
- 각 작업은 독립적인 Codex thread와 별도 폴더를 사용합니다. 역할 지침은 해당 직원의 이름·직업·업무 방식으로 구성합니다.
- 작업별 폴더에 `HANDOFF.md`를 저장하고 최종 보고서를 프로젝트 루트의 `PM-REPORT.md`에 저장합니다.
- PM 계획에는 산출물 통합 및 검증 작업을 포함하도록 요청합니다. 실제 통합 산출물은 해당 통합 담당자의 작업 폴더에 있습니다.
- 실행 실패는 후속 작업을 차단합니다. PM은 완료/미완료 결과를 취합합니다. Codex turn이 완료됐다는 사실과 산출물의 품질 검증은 별개의 사항이며, 보고서에서 검증 근거를 확인할 수 있습니다.
- 진행 중 추가 지시는 `turn/steer`로 전달합니다. 대기 작업의 지시는 실행 입력에 포함됩니다. 이미 적용된 파일 변경을 되돌리는 기능은 아닙니다.
- 중단은 `turn/interrupt`를 요청합니다. 재개는 완료 결과를 보존하고 미완료 작업을 새 thread에서 다시 실행합니다. 기존 미완료 폴더의 파일은 보존됩니다.

파일 구조:

```text
선택한 저장 폴더/
  pixel-office-output/
    프로젝트 UUID/
      _plan/                  PM 계획 세션 작업 폴더
      작업 ID/                직원별 실제 파일과 HANDOFF.md
      _report/                PM 보고 세션 작업 폴더
      PM-REPORT.md
```

앱 설정, 직원, 가구, 프로젝트, 작업 기록은 Electron 사용자 데이터 폴더의 `office.json`에 원자적으로 저장됩니다. 저장된 파일을 읽을 수 없으면 `.corrupt-시간` 백업을 남깁니다. 앱이 종료됐을 때 진행 중인 업무는 다음 실행에서 중단 상태로 표시됩니다. 이벤트 기록은 최근 600개를 보관합니다.

## 화면 기능

- 코드로 조립한 블록 캐릭터와 3D 오피스, 마우스 회전·확대·축소
- 직원 생성: 이름, 직업, 의상 색상, 역할 지침 (최대 12명)
- 캐릭터 선택: 현재 업무, 관찰 가능한 메시지·도구 실행 이벤트, 추가 지시
- 화분·책장·소파 추가 (최대 10개, 정해진 위치에 배치)
- 업무 보드, 결과 전달 타임라인, PM 보고서 저장
- 프로젝트 기록 선택, 중단 및 미완료 작업 재개
- 명령 실행·파일 변경 승인 요청에 대한 사용자 응답

## 현재 범위

- 한 번에 프로젝트 하나를 실행하며, 프로젝트 내부의 작업을 병렬 처리합니다.
- 직원은 호스트가 관리하는 독립 Codex 세션입니다. Codex가 임의로 추가 서브 에이전트를 생성하도록 맡기지 않습니다.
- 직원 간 전달은 작업 의존관계에 따른 결과 인계입니다. 자유 대화형 회의, 자동 재작업 루프, 부서별 방, 가구 드래그 배치는 아직 없습니다.
- 별도 산출물 폴더에서 새 작업을 만듭니다. 기존 저장소를 자동으로 복제하거나 수정·병합하는 기능은 없습니다.
- 실패한 작업은 재개로 다시 실행할 수 있습니다. 이미 완료된 작업을 수정 지시로 되돌려 재실행하는 기능은 없습니다.
- 지원하지 않는 Codex 상호작용 도구 요청에는 오류를 반환합니다. 명령/파일 승인 외의 질문 폼과 특별한 MCP 인증 흐름은 지원하지 않습니다.
- 에이전트의 내부 사고 전체를 표시하지 않습니다. 스트리밍 메시지와 실제 실행 이벤트를 표시합니다.
- Codex 실행 바이너리와 계정은 별도로 필요하며 EXE에 포함하지 않습니다. 자동으로 계정 토큰을 복사하지 않습니다.
- Windows portable EXE는 코드 서명되지 않은 개발 빌드입니다.

## 개발 및 검증

```powershell
npm test             # 업무 엔진 회귀 테스트
npm run build        # UI 빌드
npm run test:ui      # 실제 Electron Playwright UI 테스트
npm run check:codex   # 계정 종류와 모델 목록 조회 (추론 없음)
node scripts/live-smoke.cjs # 실제 계정 사용량을 소비하는 작은 병렬 연동 테스트
npm run package      # Windows portable EXE 생성
```

`npm run dev`는 브라우저 화면 미리보기입니다. 실제 업무 실행과 저장은 Electron에서만 가능합니다. 자동 테스트의 스크린샷은 `test-results/`에 저장됩니다. `PIXEL_OFFICE_DATA`로 테스트용 앱 데이터 경로를, `PIXEL_OFFICE_CODEX`로 Codex 실행 경로를 지정할 수 있습니다.

검증 결과: 엔진 테스트 10개, Electron UI 시나리오, 실제 ChatGPT 로그인 기반 병렬 파일 생성 → 결과 인계 → 통합 파일 검증 → PM 보고를 통과했습니다. 실제 연동 테스트에서는 독립 작업 2개 동시 실행, 후속 전달 2건, `COMBINED.txt`의 `BLUE`/`GREEN` 두 줄을 확인했습니다. 의존성 설치 후 `npm audit`에서 0개 취약점을 확인했습니다.

## 구조

```text
electron/main.cjs       Electron 수명주기, 검증된 IPC, 로그인/폴더 선택
electron/preload.cjs    renderer에 공개하는 제한된 API
electron/codex.cjs      Codex 프로세스, JSON-RPC 요청/응답
electron/engine.cjs     계획 검증, 실행 큐, 결과 인계, 보고, 저장/복원
src/office.js          Three.js 오피스와 블록 캐릭터
src/main.js            UI, 작업 보드, 설정, 보고서
tests/engine.test.cjs   병렬화/순환/실패/중단/복원/프로토콜 회귀 테스트
```

Renderer는 Node.js 접근이 차단되며 `contextIsolation`과 sandbox를 사용합니다. 외부 탐색과 팝업을 차단하고 로그인 URL은 허용된 HTTPS 호스트만 엽니다. 작업 세션은 기본적으로 자신의 작업 폴더에 대한 쓰기 권한으로 시작하고 네트워크는 제한합니다. 필요한 권한 확장은 승인 UI에서 확인합니다. PM 계획과 보고 세션은 읽기 전용입니다.

공식 연동 참고: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [Authentication](https://learn.chatgpt.com/docs/auth).
