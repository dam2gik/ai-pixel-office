# Pixel Office

Electron + Three.js로 만든 로컬 AI 오피스입니다. CEO가 목표를 입력하면 PM이 업무를 나누고, 직원들이 독립 업무를 병렬 실행합니다. 선행 작업의 결과와 산출물 경로를 후속 담당자에게 전달한 뒤 PM이 최종 보고서를 작성합니다.

## 실행

- Windows 실행 파일: [Pixel Office v0.16.0 다운로드](https://github.com/dam2gik/ai-pixel-office/releases/tag/v0.16.0)
- 개발 중에는 소스와 테스트를 갱신하며, 빌드·EXE 패키징은 명시적으로 요청받은 경우에만 진행합니다.
- 소스에서 실행: `npm install` 후 `npm start`
- Node.js 22.12 이상이 필요합니다. 개발 검증에는 Node.js 24를 사용했습니다.

처음에는 **시뮬레이션 모드**로 시작합니다. 이 모드는 AI를 호출하거나 실제 업무 산출물을 만들지 않습니다. 앱 설정과 협업 흐름을 체험할 수 있습니다.

### 개발 중 · 층 이동 단축키

- `Q`는 윗층, `E`는 아랫층으로 이동합니다. B1↔1층도 연속으로 이동하며 최상층 5층과 최하층 B6에서는 더 넘어가지 않습니다. 전체 단면에서는 마지막으로 선택한 층을 기준으로 이동하고, 외부 보기에서 누르면 해당 층의 내부로 전환합니다.
- 자유시점에서도 `Q/E`는 층 이동입니다. 자유 비행의 높이 조절은 `R` 상승·`C` 하강으로 옮겼습니다. `H`로 인터페이스를 숨긴 상태에서도 사용할 수 있으며, 채팅·입력창·한글 조합·모달 대화상자에서는 층 단축키가 작동하지 않습니다.

### 개발 중 · 5층 확장과 카드형 공간 둘러보기

- 공간 목록의 긴 스크롤을 없애고 **공간 둘러보기** 버튼으로 여는 카드 패널로 바꿨습니다. 층을 고르면 해당 층의 공간을 네 개씩 표시하고 이전·다음 버튼으로 넘깁니다. 공간 카드를 누르면 해당 층과 방으로 이동합니다. 작은 화면에서도 목록 스크롤을 사용하지 않습니다.
- 3층에 메이커 공방·서버 연구실·프로젝트 랩·쇼케이스, 4층에 발표 강당·녹음 스튜디오·게임 라운지, 5층에 온실 정원·스카이 카페·요가·명상·전망 라운지를 추가했습니다. 제작 프린터·서버 랙·전시대·무대·객석·믹싱 콘솔·마이크·아케이드 캐비닛·식물 재배대·요가 매트와 휴식 가구를 배치했습니다.
- 외관도 5층 높이로 올리고 지붕과 태양광·공조 설비를 옥상으로 옮겼습니다. 전체 단면은 1~5층과 B1~B6의 열한 층을 모두 표시하며, 모든 층에 엘리베이터를 연결했습니다. 새 층은 엘리베이터로 이동하며 기존 B1~2층 계단을 유지합니다.
- 실제 직원의 생활 모션에 제작·연구·녹음·게임·발표 관람·온실 관리·스카이 카페·요가를 추가했습니다. 실제 업무가 들어오면 엘리베이터로 책상에 복귀합니다. 새 층에서 가구 배치를 편집하거나 일반 NPC를 고용해 배치할 수 있습니다. 이 활동은 AI 호출을 추가하지 않습니다.
- `npm run test:high-campus-ui`로 카드 페이지·층 선택·세 개의 새 층·11층 단면·5층 외관·모바일·인터페이스 숨김 복원을 확인합니다. 경로 테스트는 새 시설 접근, 실제 승강 동선과 업무 복귀, 상층 가구·NPC 이동을 검증합니다. 빌드와 EXE 패키징은 진행하지 않습니다.

### 개발 중 · 인터페이스 숨기기

- 화면 위 눈 모양 버튼 또는 `H`로 인터페이스를 숨기고 다시 표시합니다. 복원 버튼은 숨김 상태에서도 남습니다. 채팅창·층과 공간 선택·직원 이름표·열린 패널을 가리고, 다시 표시하면 패널과 카메라 상태를 유지합니다.
- 텍스트 입력·한글 조합·모달 대화상자 사용 중에는 단축키가 작동하지 않습니다. 키를 길게 눌러도 반복 토글하지 않으며 Ctrl·Alt·Meta 조합은 가로채지 않습니다. 숨김 상태에서도 기존 카메라 조작과 자유 이동을 사용할 수 있습니다. 새로 열 때는 기본 인터페이스를 표시합니다.
- `npm run test:interface-ui`는 버튼·단축키 왕복, 입력 보호, 패널과 카메라 유지, 숨김 중 자유 이동, 모바일 복원 버튼과 업무 상태 유지를 검증합니다.

### 개발 중 · 햇빛과 조명 셰이더

- **조명** 버튼에서 낮·노을·밤을 선택하고 자연광 및 실내·가로등 밝기를 조절합니다. 설정은 이 기기에 저장됩니다. 시간대별 햇빛·달빛 방향과 색온도, 부드러운 2048 그림자, 하늘 그라데이션과 태양광을 적용했습니다.
- 지상·B1·B2에는 천장 조명 기구를 추가하고 광산의 기존 갱도등과 엘리베이터 등까지 총 84개의 실내 광원을 연결했습니다. 층에 맞는 최대 8개 광원만 계산합니다. 지하에서는 직사광을 줄이고 반사광과 따뜻한 조명으로 암반과 시설을 드러냅니다. 모든 층·NPC·몬스터·전리품 표시를 유지합니다.
- 가로등 16개와 정문·카페·파고라 조명은 주변 바닥과 벽을 비춥니다. 밤에는 건물 창문이 따뜻하게 빛납니다. 유리·물·대리석에 하늘과 햇빛 반사를 추가하고 조명에는 작은 빛 번짐을 적용했습니다.
- 햇빛에만 그림자 맵 1개를 사용하고 실내·가로등은 셰이더의 제한된 거리 감쇠 근사광으로 계산합니다. 개별 조명의 차폐 그림자는 계산하지 않습니다. 시간대를 자동 재생하지 않으며 카메라와 장면이 멈추면 유휴 렌더링을 중단합니다. 캐릭터 편집 미리보기의 조명은 독립적으로 유지합니다.
- `npm run test:lighting-ui`는 실제 GLSL 컴파일, 낮·노을·밤 전환, 지하와 전체 단면, 실내·외 조명, 밝기 조절과 저장·복원, 업무 상태 유지·유휴 렌더 중단·모바일 패널을 확인합니다. 개발 코드와 테스트만 반영하며 빌드·EXE 패키징은 진행하지 않습니다.

### v0.15.1 지하 전체 보기 복원

- `npm run test:section-ui`는 여덟 층과 지하 NPC·몬스터의 표시, 명령창 위의 전체 단면·층 이름표, 층 집중 보기, 외부·자유시점 왕복, 모바일 화면과 유휴 렌더 중단을 검증합니다.

### v0.15 건물 외부 · 도로와 공원

- 오른쪽 **건물 내부 / 건물 외부** 버튼으로 전환합니다. 외부에서는 지붕·외벽·창문·출입문·캐노피·간판을 갖춘 닫힌 건물 외관을 표시합니다. 지붕에는 태양광 패널과 공조 설비를 배치했습니다. 내부로 돌아오면 이전에 보던 층과 회전 카메라 위치를 복원합니다.
- 외부 부지는 180×152 크기입니다. 양방향 순환 도로·차선·횡단보도·인도, 24면 주차장과 주차 차량 16대, 충전기·차단기·경비 부스, 연못·산책로·파고라·벤치·운동 코트·카페 키오스크, 버스 정류장·자전거 거치대·가로등·휴지통·전기함과 추가 나무 22그루를 배치했습니다. 기존 정원도 외부에서 볼 수 있습니다.
- 차량 16대가 서로 분리된 두 차로를 반대 방향으로 순환합니다. 차간 간격을 유지하며 건물과 주차 구역을 침범하지 않습니다. **차량 운행 중** 버튼으로 일시정지·재개합니다. 차량은 로컬 시각 효과이며 실제 AI 업무를 생성하지 않습니다.
- **부지 전체 / 건물 앞 / 주차장 / 산책 공원** 바로가기와 기존 자유시점을 모두 사용할 수 있습니다. 외부에서는 내부 시설과 직원·NPC 모델을 렌더링하지 않습니다. 고정 외부 오브젝트와 주차 차량은 일괄 렌더링하고, 운행 차량은 17개 공유 인스턴스 풀로 그립니다. 차량을 정지하고 카메라도 멈추면 유휴 렌더링이 중단됩니다.
- `npm run test:exterior-ui`로 외부 표시·차량 이동과 일시정지·시점 바로가기·자유시점·기존 층과 카메라 복원·업무 상태 유지·모바일 화면을 검증합니다. 경로 단위 테스트는 도로 이탈과 차량 중첩을 확인합니다.

### v0.14 자유시점 · 렌더링 최적화

- 오른쪽 아래 **자유시점 · F** 버튼 또는 `F`로 전환합니다. `W/A/S/D`로 시선 방향 전후·좌우 이동, `Q/E`로 윗층·아랫층 이동, `R/C`로 상승·하강, `Shift`로 빠른 이동, 마우스 오른쪽 드래그로 둘러봅니다. `Esc` 또는 `F`로 기존 회전 시점으로 돌아옵니다. 벽을 통과할 수 있는 자유 비행 방식입니다.
- 층 선택 시 해당 층의 눈높이에서 시작하며, 초기화 버튼으로 다시 시작 위치에 돌아갑니다. 채팅·입력칸·대화상자 사용 중에는 이동 입력을 차단하고, 창에서 포커스를 잃으면 눌린 키를 해제합니다. 가구 편집과 직원·공간 집중 보기는 기존 회전 시점으로 전환됩니다.
- 이동 중 렌더 배율은 1.25로 낮추고 멈추면 기존 1.5~2로 복원합니다. 고정 지형·가구의 로컬 행렬 계산을 동결하고, 정지한 NPC 데이터는 재사용하며, 움직이는 NPC는 사용하는 버퍼 구간만 GPU에 전송합니다. 보이지 않는 층 제외와 유휴 렌더 중단을 유지합니다.
- `npm run test:free-camera-ui`는 이동·상승·가속·마우스 회전·입력창 보호·포커스 해제·층 전환·해상도 복원·NPC 버퍼 재사용·모바일 표시를 실제 화면에서 확인합니다.

### v0.13 불규칙 광산 · 몬스터 · 골드 상점

- B3~B6를 층마다 다른 굽은 갱도와 갈라지는 레일, 높이·방향이 불규칙한 암반, 낙석·광맥으로 구성했습니다. 엘리베이터는 B6까지 연결됩니다.
- B5/B6에서 슬라임·동굴박쥐·암석괴물이 무작위로 생성됩니다. 기본 정원은 층당 6마리이며 상점에서 0~12마리로 조절합니다. 전체 최대 24마리이고 몬스터는 태어난 층에서만 이동·공격합니다.
- 일반 NPC는 처음 5명, 총 최대 40명입니다. 실제 Codex 직원과 별개로 채굴·경비·산책을 수행하며 AI를 호출하지 않습니다. 고용 상점에서 직무와 배치 층을 고릅니다. 첫 추가 고용은 150골드이고 이후 25골드씩 증가합니다.
- 채굴 NPC가 작업을 마치면 석탄·구리·철·은·금·수정을 얻습니다. 몬스터 처치 시 젤·날개·핵이 해당 층에 떨어지고 NPC가 수거합니다. 오른쪽 골드 버튼에서 보유 자원과 전리품을 판매해 고용 비용을 마련합니다.
- 몬스터 정원·골드·재고·NPC 고용 상태를 저장합니다. 거래는 즉시 저장하고 진행 상태는 5초마다 저장합니다. 앱을 실행 중일 때만 시간이 흐르며, 패널에서 전체 진행 또는 개별 NPC를 일시정지할 수 있습니다.
- NPC와 몬스터는 배치된 층의 통행 가능한 경로를 따라 이동합니다. 몬스터 정원을 낮추어 제거된 개체는 전리품을 주지 않습니다. 일반 NPC는 인스턴스 렌더링을 사용합니다.
- `npm run test:game-ui`는 실제 채굴·전투 수익 판매, 추가 35명 고용, 40명 표시, 몬스터 정원 변경, 저장·복원과 모바일 화면을 검증합니다. 단위 테스트는 층 이탈·벽 통과·중복 수거·잘못된 거래와 실제 에이전트 상태 분리를 확인합니다.

### v0.3 넓어진 오피스와 생활 모션

- 맵을 15×11에서 **32×22**로 확장했습니다. 워크스페이스, 커피 머신·냉장고·간식장이 있는 탕비실, 안마의자 2대와 소파가 있는 휴게실, 화이트보드·회의 테이블·스크린이 있는 회의실, 칸막이와 세면대가 있는 화장실을 추가했습니다.

- 움직이는 직원에는 가벼운 접지 그림자를 사용하고, 방과 가구의 그림자는 구성이 변경될 때만 다시 계산합니다. 정적 블록 인스턴싱과 로컬 Pretendard는 유지했습니다.
- 12개 책상에서 모든 시설까지 도달하는 경로, 벽·가구 충돌, 좌석 예약, 화장실 후 손 씻기, 업무 복귀, 모션 정지, 직원 추가 시 상태 보존을 테스트했습니다. 엔진 10개와 생활 시뮬레이션 5개, Electron 화면 테스트를 통과했습니다. 초기 4명 확장 맵의 draw call은 테스트 환경 기준 149회입니다.

- 픽셀 비율을 최대 1.5로 제한하고 그림자 맵을 1024로 줄였습니다. 정적인 그림자는 직원·가구 구성이 바뀔 때 갱신합니다. 캐릭터의 작은 작업 동작마다 그림자를 다시 계산하지 않습니다.
- 가구 변경 시 직원을 다시 생성하지 않고, 공유 geometry/material을 재사용합니다. DOM 이름표는 좌표가 달라질 때만 수정하고, 실시간 메시지 UI 업데이트는 모아서 반영합니다.
- 실제 Electron 테스트에서 초기 4명 장면의 draw call 81회, 유휴 1초간 추가 렌더 0회, 작업 애니메이션 1초간 29프레임, 최소화 상태 추가 렌더 0회를 확인했습니다. 수치는 테스트 환경 기준이며 직원·가구 수와 디스플레이에 따라 달라집니다. 측정 파일: `test-results/render-metrics.json`.

## 실제 Codex 사용

1. 설정 → **연결 확인**을 누릅니다. 설치된 `codex` 또는 VS Code Codex 확장의 실행 파일을 자동으로 찾습니다. 자동 탐색이 실패하면 `codex.exe`를 직접 선택하세요.
2. 기존 ChatGPT 로그인을 사용할 수 있으면 연결됩니다. 필요한 경우 **ChatGPT로 로그인**을 누르고 기본 브라우저에서 로그인한 다음 다시 연결을 확인하세요.
3. 설정에서 기본 프로젝트 폴더를 지정할 수 있습니다. 기존 설정의 저장 폴더도 그대로 사용합니다.
4. 실행 모드를 **Codex**로 변경하고 저장합니다. 병렬 실행은 1~6개로 설정할 수 있습니다.
5. CEO 지시창에서 업무를 맡깁니다. 기본 폴더를 그대로 사용하며, **이번 업무의 폴더 변경**을 선택한 경우에만 폴더 선택창이 열립니다. 선택을 취소하면 업무는 시작하지 않고 입력한 요청은 유지합니다. 캐릭터나 직원 목록을 클릭하면 실행 내용 확인 및 추가 지시가 가능합니다.
6. **협업 기록**에서 직원 간 결과 전달을, **PM 보고서**에서 최종 보고와 산출물 폴더를 확인하세요.
7. 결과가 나오면 **검수 대기** 상태입니다. **대화 · 검수** 탭과 하단 입력창에서 수정·추가 요청을 같은 프로젝트에 계속 보낼 수 있습니다. 사용자가 **검수 완료 · 종료**를 눌러야 프로젝트가 완료됩니다. 별도 목표는 **새 프로젝트**로 시작하세요.

별도 OpenAI API 키는 사용하지 않습니다. 앱은 ChatGPT 로그인 유형을 확인하고 실행하며, 사용량과 모델 접근 권한은 해당 계정의 Codex 이용 조건을 따릅니다. Windows ChatGPT 앱 자체를 화면 자동화하는 방식은 아닙니다. 공식 로컬 `codex app-server`와 통신합니다.

## 구현된 협업 방식

- AI 실행 종료와 사용자 검수 완료를 구분합니다. 성공한 실행은 `review`(검수 대기), 사용자 완료 처리는 `completed`와 `userCompletedAt`으로 저장합니다. 이전 버전에서 자동 완료된 기록은 검수 대기로 전환해 이어서 요청할 수 있습니다.
- 후속 요청은 같은 프로젝트 ID·폴더에서 2차·3차 작업으로 이어집니다. 이전 요청·보고서·작업·파일을 보존하고 대화 이력과 산출물 경로를 다음 담당자에게 전달합니다. `PROJECT-HISTORY.md`에 전체 요청·결과를 저장하며, 후속 산출물은 `round-N` 하위에 만듭니다. 직원별 세션은 앱이 켜져 있는 동안 후속 요청에도 재사용하고, 앱 재시작 후에는 저장된 이력으로 새 세션에서 이어갑니다.

- 새 업무에 프로젝트 폴더를 선택적으로 지정할 수 있습니다. 지정하지 않으면 기본 폴더를 사용합니다. 선택한 폴더는 업무별 `projectDirectory`에 저장되고 다음 요청의 기본값으로도 사용합니다. 직원들은 해당 폴더의 기존 파일과 지침을 참고하고, 산출물·변경본은 그 아래 `pixel-office-output/업무 UUID/작업 ID`에 저장합니다. 재개할 때는 원래 업무의 폴더를 유지합니다.

- 기본 **자동** 모드에서는 문구·오타·색상 수정 등 명확한 소규모 요청을 담당자 한 명이 실행·검증합니다. 별도의 AI 분류 호출이나 PM 계획·보고 호출 없이 담당자 결과로 보고서를 만듭니다. 복잡하거나 모호한 목표는 PM이 구조화된 계획을 작성합니다. 설정에서 단독 처리 또는 PM 배정을 지정할 수도 있습니다.
- 실행 큐가 동시 실행 수를 제한합니다. 같은 직원에게 동시에 두 작업을 맡기지 않습니다.
- 선행 작업이 모두 완료되면 후속 작업을 실행합니다. 후속 작업이 긴 업무를 먼저 시작하며, 담당자가 바쁘면 PM이 지정한 적임자 또는 같은 직무의 유휴 직원에게 아직 시작하지 않은 작업을 재배정합니다. 전문성이 다른 직무로 임의 배정하지 않습니다.
- 선행 결과는 최대 1,600자의 발췌와 산출물·`HANDOFF.md` 경로로 전달합니다. 담당자는 필요한 전체 결과를 파일에서 읽습니다. 여러 산출물의 통합·검증은 요청 조건이 허용하면 한 작업으로 합치도록 계획합니다.
- 작업별 폴더는 분리하고, 같은 프로젝트의 같은 직원·권한에서 완료된 Codex thread를 다음 작업에 재사용합니다. 매 턴 `cwd`와 쓰기 허용 폴더를 현재 작업 폴더로 지정합니다. PM 계획·보고는 읽기 전용이며 실행 세션과 분리합니다. 실패·중단·재개·다른 프로젝트에서는 새 세션을 사용합니다.
- 직원을 클릭한 뒤 **결과물 미리보기**에서 해당 직원의 파일과 작업 결과 요약을 확인합니다. 이미지, 텍스트·코드·Markdown, HTML 정적 화면을 지원하며 새로고침으로 작업 중 생성된 파일도 확인할 수 있습니다. HTML의 스크립트와 외부 리소스는 실행하지 않습니다. 지원하지 않는 형식은 산출물 폴더에서 확인합니다.
- 작업별 폴더에 `HANDOFF.md`를 저장하고 최종 보고서를 프로젝트 루트의 `PM-REPORT.md`에 저장합니다.
- PM 계획에는 산출물 통합 및 검증 작업을 포함하도록 요청합니다. 실제 통합 산출물은 해당 통합 담당자의 작업 폴더에 있습니다.
- 실행 실패는 후속 작업을 차단합니다. PM은 완료/미완료 결과를 취합합니다. Codex turn이 완료됐다는 사실과 산출물의 품질 검증은 별개의 사항이며, 보고서에서 검증 근거를 확인할 수 있습니다.
- 진행 중 추가 지시는 `turn/steer`로 전달합니다. 대기 작업의 지시는 실행 입력에 포함됩니다. 이미 적용된 파일 변경을 되돌리는 기능은 아닙니다.
- 중단은 `turn/interrupt`를 요청합니다. 재개는 완료 결과를 보존하고 미완료 작업을 새 thread에서 다시 실행합니다. 기존 미완료 폴더의 파일은 보존됩니다.
- 프로젝트별 `metrics`에 새 세션·재사용·AI 실행 횟수, 최대 동시 작업 수, 계획·실행·보고·누적 소요 시간을 기록합니다. 업무 보드에는 처리 방식과 동시 작업 수·누적 실행 시간이 표시됩니다. 실제 속도는 요청 크기와 계정 상태에 따라 달라집니다.
- 진행 텍스트는 80ms, 명령 로그의 저장·상태 전송은 120ms 단위로 묶습니다. 최종 결과와 승인·중단·완료 등의 상태 변경은 즉시 반영하며, 종료할 때 대기 중인 로그도 저장합니다. 로그만 바뀌면 직원 목록·3D 상태를 다시 만들지 않고, 닫힌 직원 상세 패널은 갱신하지 않습니다.
- `npm run benchmark:events`는 AI 호출 없이 텍스트 조각 1,000개·명령 100건·과거 프로젝트 10개를 재생하여 로컬 저장·전송 횟수와 처리 시간을 측정합니다. AI 응답 속도 측정과는 별개입니다.

파일 구조:

```text
선택한 저장 폴더/
  pixel-office-output/
    프로젝트 UUID/
      _plan/                  PM 계획 세션 작업 폴더
      작업 ID/                직원별 실제 파일과 HANDOFF.md
      _report/                PM 보고 세션 작업 폴더
      PM-REPORT.md
```

앱 설정, 직원, 가구, 프로젝트, 작업 기록은 Electron 사용자 데이터 폴더의 `office.json`에 원자적으로 저장됩니다. 저장된 파일을 읽을 수 없으면 `.corrupt-시간` 백업을 남깁니다. 앱이 종료됐을 때 진행 중인 업무는 다음 실행에서 중단 상태로 표시됩니다. 이벤트 기록은 최근 600개를 보관합니다.

## 화면 기능

- 코드로 조립한 블록 캐릭터와 3D 오피스, 마우스 회전·확대·축소
- 직원 생성: 이름, 직업, 의상 색상, 역할 지침 (최대 12명)
- 캐릭터 선택: 현재 업무, 관찰 가능한 메시지·도구 실행 이벤트, 추가 지시
- 소품 6종 추가·드래그 이동·좌표 이동·회전·층 이동·삭제 (최대 60개, 자동 저장)
- 업무 보드, 결과 전달 타임라인, PM 보고서 저장
- 프로젝트 기록 선택, 중단 및 미완료 작업 재개
- 명령 실행·파일 변경 승인 요청에 대한 사용자 응답

## 현재 범위

- 한 번에 프로젝트 하나를 실행하며, 프로젝트 내부의 작업을 병렬 처리합니다.
- 직원은 호스트가 관리하는 독립 Codex 세션입니다. Codex가 임의로 추가 서브 에이전트를 생성하도록 맡기지 않습니다.
- 직원 간 전달은 작업 의존관계에 따른 결과 인계입니다. 자유 대화형 회의, 자동 재작업 루프, 부서별 방은 아직 없습니다. 배치 편집은 추가한 가구에 적용되며 고정 시설과 담당 책상은 유지됩니다.
- 별도 산출물 폴더에서 새 작업을 만듭니다. 기존 저장소를 자동으로 복제하거나 수정·병합하는 기능은 없습니다.
- 실패한 작업은 재개로 다시 실행할 수 있습니다. 완료된 결과의 수정은 같은 프로젝트에 추가 요청을 보내 새 차수에서 처리하며, 이전 파일은 보존합니다.
- 지원하지 않는 Codex 상호작용 도구 요청에는 오류를 반환합니다. 명령/파일 승인 외의 질문 폼과 특별한 MCP 인증 흐름은 지원하지 않습니다.
- 에이전트의 내부 사고 전체를 표시하지 않습니다. 스트리밍 메시지와 실제 실행 이벤트를 표시합니다.
- Codex 실행 바이너리와 계정은 별도로 필요하며 EXE에 포함하지 않습니다. 자동으로 계정 토큰을 복사하지 않습니다.
- Windows portable EXE는 코드 서명되지 않은 개발 빌드입니다.

## 개발 및 검증

```powershell
npm test             # 업무 엔진 회귀 테스트
npm run build        # UI 빌드
npm run test:ui      # 실제 Electron Playwright UI 테스트
npm run check:codex   # 계정 종류와 모델 목록 조회 (추론 없음)

```

`npm run dev`는 브라우저 화면 미리보기입니다. 실제 업무 실행과 저장은 Electron에서만 가능합니다. 자동 테스트의 스크린샷은 `test-results/`에 저장됩니다. `PIXEL_OFFICE_DATA`로 테스트용 앱 데이터 경로를, `PIXEL_OFFICE_CODEX`로 Codex 실행 경로를 지정할 수 있습니다.

검증 결과: 엔진 테스트 10개, Electron UI 시나리오, 실제 ChatGPT 로그인 기반 병렬 파일 생성 → 결과 인계 → 통합 파일 검증 → PM 보고를 통과했습니다. 실제 연동 테스트에서는 독립 작업 2개 동시 실행, 후속 전달 2건, `COMBINED.txt`의 `BLUE`/`GREEN` 두 줄을 확인했습니다. 의존성 설치 후 `npm audit`에서 0개 취약점을 확인했습니다.

## 구조

```text
electron/main.cjs       Electron 수명주기, 검증된 IPC, 로그인/폴더 선택
electron/preload.cjs    renderer에 공개하는 제한된 API
electron/codex.cjs      Codex 프로세스, JSON-RPC 요청/응답
electron/engine.cjs     계획 검증, 실행 큐, 결과 인계, 보고, 저장/복원
src/office.js          Three.js 오피스와 블록 캐릭터
src/main.js            UI, 작업 보드, 설정, 보고서
tests/engine.test.cjs   병렬화/순환/실패/중단/복원/프로토콜 회귀 테스트
```

Renderer는 Node.js 접근이 차단되며 `contextIsolation`과 sandbox를 사용합니다. 외부 탐색과 팝업을 차단하고 로그인 URL은 허용된 HTTPS 호스트만 엽니다. 작업 세션은 기본적으로 자신의 작업 폴더에 대한 쓰기 권한으로 시작하고 네트워크는 제한합니다. 필요한 권한 확장은 승인 UI에서 확인합니다. PM 계획과 보고 세션은 읽기 전용입니다.

공식 연동 참고: [Codex App Server](https://learn.chatgpt.com/docs/app-server), [Authentication](https://learn.chatgpt.com/docs/auth).
